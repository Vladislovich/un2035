# Наземная станция БПЛА: инструкция

Дрон (Orange Pi 3B) находит людей, дым и ArUco-маркеры и шлёт на ПК находки,
телеметрию и живое видео. ПК считает координаты объектов (формула Миши) и
показывает всё в браузере: видео с рамками, кадры находок, карту, журнал.

```
ДРОН: Orange Pi 192.168.0.32 (onboard/)          ПК 192.168.0.38 (station/)
  камера USB → YOLO на NPU (люди, дым)            ground_bridge.py
             → ArUco на CPU (DICT_4X4_50)           :5700 приём находок
  полётник Betaflight по USB (MSP)                  :5701 приём видео
  находки ──TCP 5700, очередь + подтверждения──►    :8080 веб-интерфейс
  видео   ──TCP 5701, только свежий кадр───────►
```

- **Дрон сам подключается к ПК** и переподключается после обрывов. Удобнее сначала
  запустить станцию, потом борт, но можно и наоборот: борт подождёт.
- **Находки идут надёжно.** Они лежат в очереди на плате, пока ПК не подтвердит приём.
- **Видео идёт без гарантий** (640 px, 4–5 к/с). При плохой связи кадры пропускаются,
  находкам это не мешает.

## 1. Подготовка (один раз)

### ПК
- Нужен только Python 3.8+. Для имитатора дрона ещё `pip install opencv-python`.
- ПК и плата должны быть в одной сети `192.168.0.x`.
- Если включены VPN или файрвол, пропустить входящие на порты 5700 и 5701.
  Иначе дрон не достучится до ПК.

### Orange Pi
Подключить плату к Wi‑Fi (см. `orangepi-wifi.md`), затем собрать программу:
```bash
ssh orangepi@192.168.0.32
sudo apt install build-essential cmake pkg-config libopencv-dev \
     libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev gstreamer1.0-plugins-good v4l-utils
cd ~/un2035/onboard
cmake -B build -DCMAKE_BUILD_TYPE=Release -DRKNN_ROOT="$PWD/third_party/rknpu2"
```
Команду `cmake -B build ...` выполнить **обязательно**: без неё `run.sh` не соберёт
программу. Повторить её, если папка `build/` удалена.

Если `cv::aruco` не находится, поставить `libopencv-contrib-dev`.

Вход на плату без пароля: на ПК выполнить `ssh-keygen -t ed25519`, затем
`ssh-copy-id orangepi@192.168.0.32`. Стандартный пароль платы лучше сменить (`passwd`).

## 2. Запуск

### ПК: станция
```bash
cd station
python3 ground_bridge.py --dir finds_поле_2
```
Открыть http://localhost:8080. Станция печатает свой адрес в сети: его нужно указать
дрону в `SAR_GROUND_IP`. Остановить станцию — `Ctrl+C`.

### Orange Pi: борт
```bash
ssh orangepi@192.168.0.32
cd ~/un2035/onboard
SAR_GROUND_IP=192.168.0.38 ./run.sh test
```
- `192.168.0.38` — адрес ПК. Если ПК получил другой адрес по DHCP, подставить его.
- `test` — проверка на столе: координаты подставные (башня Политеха, 30 м), углы
  настоящие с полётника. Без `test` — боевой режим, координаты с GPS полётника.
- `./run.sh test 640` — камера 640×480, если 720p не тянет по кадрам.
- Камеру `run.sh` находит сам: номер `/dev/videoN` может меняться. Формат (MJPG или
  YUYV) и размер выбираются из того, что умеет камера. Для этого нужен пакет
  `v4l-utils`. Задать камеру вручную: `SAR_CAMERA=/dev/video1`.
- Если камера отвалилась на ходу, программа перезапускается сама и ждёт, пока
  камера появится снова.
- Остановить — `Ctrl+C`.

`run.sh` пересобирает программу, если менялись исходники. Перед запуском он проверяет,
что порт полётника свободен.

Через несколько секунд в интерфейсе появятся «Дрон на связи», видео и позиция.

Чтобы программа работала после закрытия SSH:
```bash
SAR_GROUND_IP=192.168.0.38 nohup ./run.sh test > run.log 2>&1 &
tail -f run.log
pkill -INT -f "[b]uild/sar_yolo_pipeline"      # остановить
```

### Проверка без дрона
На ПК, в двух окнах:
```bash
cd station
python3 ground_bridge.py --dir finds_sim
python3 sim_drone.py      # летает по кругу, раз в 5 с шлёт находку из demo.mp4
```

## 3. Новое место, новый вылет

Станция при запуске загружает все прошлые находки из папки, указанной в `--dir`.
Для нового места нужно новое имя папки, например `--dir finds_поле_3`. Чтобы вернуться
к старым находкам, запустить станцию с их `--dir`.

В каждой папке лежат журнал `events.jsonl`, кадры находок и `telemetry.jsonl`.

**Очередь на борту.** Недоставленные находки лежат на плате в `onboard/queue/` и уйдут
на станцию при следующем подключении, даже в новом месте. Если они не нужны,
остановить программу и удалить их:
```bash
ls ~/un2035/onboard/queue | wc -l     # сколько
rm ~/un2035/onboard/queue/*           # удалить
```
Полные кадры находок борт пишет в `onboard/finds/`. На станцию они не влияют. Если
кончается место, их можно удалить (`du -sh ~/un2035/onboard/finds`).

## 4. Интерфейс

- **Верхняя строка:** связь, высота, позиция дрона, время, GPS. Надпись «ТЕСТОВАЯ ПОЗА»
  означает, что координаты подставные.
- **Монитор:** живое видео. Пунктир — детекции кадра: оранжевый — человек,
  бирюзовый — ArUco. Мигание рамок — это нормально.
- **Клик по находке:** её кадр с рамкой, координаты объекта и дрона. «К живому видео»
  возвращает к видео.
- **Карта:** дрон, след, пятно обзора камеры, метки находок. Клик по метке
  показывает круг ошибки ±N м (95 %).
- **Журнал:** подтвердить ✓, отметить ложной ✗, скопировать координаты. Один ArUco-маркер
  занимает одну строку, повторы её обновляют. Отметки хранятся в браузере отдельно для
  каждой папки. Кнопка «Сбросить отметки» их очищает.
- **«Борт»:** состояние полётника, углы, расхождение с бортовым расчётом.

**Когда находка попадает в журнал.**
- **Человек:** 3 срабатывания нейросети за 2 с, не чаще раза в 5 с.
- **Маркер:** 2 кадра подряд, повтор не чаще 15 с (в режиме `test` — 2 с).
- **Трекера нет:** один и тот же человек приходит новой находкой раз в 5 с.

## 5. Настройки

### Переменные окружения на борту (без пересборки)
| Переменная | По умолчанию | Что делает |
|---|---|---|
| `SAR_GROUND_IP` | 192.168.3.24 | адрес ПК |
| `SAR_CAMERA` | ищется сама | устройство камеры, например `/dev/video1` |
| `SAR_FC_URI` | Foxeer by-id | порт полётника; пусто — без полётника |
| `SAR_FAKE_POSE` | выкл (в `test` вкл) | подставная позиция `шир,долг,высота` |
| `SAR_ARUCO` | 1 | `0` — не искать маркеры |
| `SAR_ARUCO_REPEAT_S` | 15 (test: 2) | повтор одного маркера, с |
| `SAR_ARUCO_GAP_S` | 1.5 | если маркер пропал дольше, это новая встреча |
| `SAR_VIDEO` | 1 | `0` — без видео |
| `SAR_VIDEO_FPS` | 5 | кадров видео в секунду (8–10 плавнее, около 2 Мбит/с) |
| `SAR_VIDEO_WIDTH` | 640 | ширина кадра видео |
| `SAR_VIDEO_JPEG` | 60 | качество JPEG |

### Константы в `onboard/src/main.cpp` (после изменения запустить `./run.sh`, он пересоберёт)
| Константа | Сейчас | Перед полётом проверить |
|---|---|---|
| `CAMERA_HFOV_DEG` | 62 | угол обзора по даташиту; ошибка 5 % даёт ≈ 1.3 м на 80 м |
| `CAMERA_TILT_DEG` | 0 | 0 — камера строго вниз, верх кадра смотрит на нос; ошибка 2° даёт ≈ 2.9 м на 80 м |
| `CAMERA_PAN_DEG` | 0 | поворот камеры вокруг вертикали |
| `CAPTURE_LATENCY_US` | 120 мс | задержка камеры; ошибка сносит метки вдоль полёта |
| `CONF_THRESHOLD` | 0.35 | порог уверенности нейросети |

Станции HFOV и наклон нужны только для пятна обзора на карте:
`python3 ground_bridge.py --hfov 62 --tilt 0`.
Порты станции: `--tcp-port` (5700), `--video-port` (5701), `--port` (8080).

## 6. Если не работает

| Симптом | Что сделать |
|---|---|
| «Жду подключения дрона» | проверить с платы: `timeout 5 bash -c "</dev/tcp/192.168.0.38/5700" && echo OK`. «Connection refused» — станция не запущена или указан не тот адрес. Таймаут — мешает файрвол или VPN |
| «Порт 5700 занят» | уже запущена вторая станция, `ground_server.py` или `viewer.py`. Порт может слушать только одна программа |
| Видео встало после встряски, в логе «камера потеряна» | отошёл кабель USB-камеры. Через несколько секунд `run.sh` сам перезапустит программу. Кабель закрепить стяжкой или термоклеем |
| «камера не найдена, жду...» | камера не подключена или не видна системе. Проверить `v4l2-ctl --list-devices` |
| «Не удалось открыть камеру» по кругу | камера не отдаёт кадры в выбранном формате. Ошибка GStreamer напечатана строкой выше. Попробовать `./run.sh test 640` или указать другой узел через `SAR_CAMERA` |
| Полётник занят или молчит | закрыть Betaflight Configurator или `msp_probe.py`. Проверить `ls -l /dev/serial/by-id/` |
| Нет фикса GPS, находки без координат | на улице дождаться фикса 3 и не меньше 6 спутников. Высота считается от точки взлёта, поэтому взводить дрон на земле в месте старта |
| ArUco не находится | нужен словарь 4×4 (номера 0–49) с белым полем вокруг чёрной рамки, минимум в одну клетку. Маркеры 6×6 не распознаются |
| Рамка маркера подрагивает | маркер ищется на соседнем кадре, а видео идёт 4–5 к/с. Это известное ограничение |
| Задержки и обрывы Wi‑Fi | на плате выключить энергосбережение: `sudo iw dev wlan0 set power_save off` |
| Неверное время в интерфейсе | время берётся с часов платы, проверить `date` |

### Отличия от исходного кода Иры
1. `include/Finding.hpp`: в метку находки добавлены пиксель, рамка, размер кадра,
   параметры камеры и поза дрона на момент кадра. Старые поля не менялись.
2. `src/main.cpp`: исправлен баг с пустой находкой человека (уверенность 0, рамка
   `[0,0,0,0]`). Теперь находка отправляется только из кадра, где цель есть.
3. `include/LiveVideo.hpp` (новый) и `src/main.cpp`: живое видео на порт 5701
   и рамки ArUco в видео.
4. `include/FindingImage.hpp` и `tools/ground_server.py` взяты из более новой версии
   Иры: там исправлены рисование рамки и приём телеметрии.
