# Наземная станция + борт: запуск и нюансы

Состояние на 21.10.2026. Проверено на настоящей плате: камера, NPU, полётник,
находки, живое видео, карта. Позиция в проверках была **тестовая** (стол, без GPS).

---

## 1. Как это устроено

```
 ДРОН (Orange Pi 3B, 192.168.3.50)                     НОУТБУК (свой IP)      
 ~/sar_yolo_pipeline/build/sar_yolo_pipeline           ground_bridge.py
   камера USB -> YOLO на NPU (люди, дым)                 приём находок  :5700
              -> ArUco на процессоре (DICT_4X4_50)       приём видео    :5701
   полётник Betaflight по USB (MSP): углы, высота, GPS   формула Миши -> координаты
                                                         веб-интерфейс  :8080
   находки  --TCP 5700, очередь + подтверждения-->       (страница Кати, web/index.html)
   видео    --TCP 5701, только свежий кадр------->
```

- **Дрон сам подключается к ноутбуку** и переподключается после обрывов. Поэтому
  сначала запускается мост на ноутбуке, потом борт. Можно и наоборот — борт подождёт.
- **Находки** (человек, дым, ArUco) идут надёжно: лежат в очереди на плате, пока
  ноутбук не подтвердит. Ничего не теряется при обрыве связи.
- **Видео** (640 px, ~4–5 к/с, рамки детектора) идёт отдельно и без гарантий:
  если связь плохая, кадры просто пропускаются, находкам это не мешает.
- **Координаты объекта** считаются на ноутбуке по формуле Миши: пиксель, крен,
  тангаж, курс и высота дрона на момент кадра. Борт считает то же самое у себя;
  расхождение в проверках — 0.01 м.

## 2. Один раз: подготовка ноутбука

1. **Python 3** (любой 3.8+). Мосту ничего ставить не нужно, только стандартная библиотека.
   Для имитатора дрона (`sim_drone.py`) нужен `pip install opencv-python`.
2. **Файрвол Windows.** При первом запуске моста Windows спросит про доступ Python к сети —
   разрешить для **частных сетей**. Иначе дрон не достучится до портов 5700/5701.
3. **VPN** (например, AmneziaVPN). Если включён, он забирает себе и локальную сеть, и дрон
   становится недоступен. В Amnezia: *Раздельное туннелирование сайтов* →
   «Адреса из списка **не** должны открываться через VPN» → добавить `192.168.3.0/24`
   → **переподключить VPN**.
4. **SSH к плате:** `ssh orangepi@192.168.3.50` (пароль спросить у команды). Чтобы не вводить пароль каждый раз — настроить ключ, см. «СНАЧАЛА ПРОЧТИ.md».
   Пароль платы стандартный — лучше сменить (`passwd` на плате).

## 3. Каждый запуск

### 3.1. Ноутбук — мост и интерфейс
Двойной клик по **`Запустить станцию.bat`** в корне архива — или вручную:
```
cd <папка из архива>\station
python ground_bridge.py
```
Открыть в браузере **http://localhost:8080**. В консоли моста видно подключения
борта и каждую находку. Остановить — `Ctrl+C`.

Принятое сохраняется в `finds_web/` (журнал `events.jsonl`, кадры находок,
`telemetry.jsonl`). Как начать «с чистого листа» — раздел 3.4.

### 3.2. Дрон — бортовая программа
```
ssh orangepi@192.168.3.50
cd ~/sar_yolo_pipeline
```
**Проверка на столе** (координаты подставные — башня Политеха, 30 м; углы настоящие с полётника):
```
SAR_GROUND_IP=<IP_НОУТБУКА> ./run.sh test
```
**Боевой режим** (координаты с GPS полётника):
```
SAR_GROUND_IP=<IP_НОУТБУКА> ./run.sh
```
`run.sh` сам пересобирает программу, если исходники менялись, проверяет, что порт
полётника свободен, и запускает. Остановить — `Ctrl+C`.

> `SAR_GROUND_IP` — адрес **ноутбука** в сети, где стоит дрон. Ноутбук получает его
> по DHCP, он может поменяться: свой адрес мост печатает при запуске
> (строка вида `http://<IP_НОУТБУКА>:8080`). Без переменной `run.sh` подставит 192.168.3.24.

Если нужно, чтобы программа работала после закрытия SSH:
```
SAR_GROUND_IP=<IP_НОУТБУКА> nohup ./run.sh test > run.log 2>&1 &
tail -f run.log
pkill -INT -f "[b]uild/sar_yolo_pipeline"      # остановить
```

### 3.3. Без дрона (проверить интерфейс)
Двойной клик по **`Проверка без дрона.bat`** — или вручную:
```
python ground_bridge.py
python sim_drone.py          # во втором окне: летает по кругу и шлёт находки из demo.mp4
```


### 3.4. Начать с нуля (новое место, новый вылет)
Станция при запуске загружает **все прошлые находки** из папки `station/finds_web/`
(журнал `events.jsonl`, кадры, телеметрия) и показывает их в журнале и на карте.
Чтобы начать с чистого листа:

1. **Остановить станцию** (закрыть окно или `Ctrl+C`).
2. **Переименовать папку** `station/finds_web`, например в `finds_web_2026-10-21_лаборатория`.
   Удалять не обязательно: старые находки останутся для разбора.
3. Запустить станцию снова — журнал и карта пустые, номера находок снова с Ч1.

Удобнее — сразу давать каждому месту свою папку, ничего не переименовывая:
```
python ground_bridge.py --dir finds_поле_2
```
(или `Запустить станцию.bat --dir finds_поле_2`). Вернуться к старым находкам —
запустить с их `--dir`.

**Отметки ✓ / ✗** хранятся в браузере отдельно для каждой папки. Если папку
переименовали, а новую назвали так же (`finds_web`), старые отметки могут прилипнуть к
новым находкам с теми же номерами — нажать **«Сбросить отметки»** над журналом.
С новым именем папки (`--dir ...`) такой проблемы нет.

**Очередь на борту.** Находки, которые борт не успел доставить, лежат на плате в
`~/sar_yolo_pipeline/queue/` и уйдут на станцию при следующем подключении — даже в
новом месте. Обычно очередь пустая (видно в логе борта: «в очереди 0»). Если там
остались старые и они не нужны — на плате, **при остановленной** программе:
```
ls ~/sar_yolo_pipeline/queue | wc -l      # сколько
rm ~/sar_yolo_pipeline/queue/*            # удалить
```
Полные кадры находок борт ещё пишет себе в `~/sar_yolo_pipeline/finds/` — на станцию
они не влияют, их можно чистить, если кончается место (`du -sh ~/sar_yolo_pipeline/finds`).

## 4. Что показывает интерфейс

- **Верхняя строка:** связь с дроном, высота, позиция дрона, время, GPS (фикс и спутники).
  «ТЕСТОВАЯ ПОЗА» — координаты подставные, в полёт так нельзя.
- **Монитор:** живое видео. Пунктир — сырые детекции этого кадра
  (оранжевый — человек, бирюзовый — ArUco-маркер). Они могут мигать — это нормально.
- **Клик по находке в журнале** — на мониторе её кадр со сплошной рамкой,
  координаты объекта и дрона в момент кадра. **«К живому видео»** — назад к потоку.
- **Карта:** дрон, его след, пятно обзора камеры, метки находок. Клик по метке —
  круг ошибки ±N м (95 %).
- **Журнал:** подтвердить ✓ / отметить ложной ✗ / скопировать координаты.
  Один и тот же ArUco-маркер — одна строка, повторы её обновляют.
- **«Борт»** (кнопка вверху): состояние полётника, углы, расхождение с бортовым расчётом.

**Когда человек попадает в журнал:** 3 срабатывания нейросети за 2 секунды,
не чаще раза в 5 секунд на класс. **Маркер:** 2 кадра подряд, повтор не чаще 15 с
(в тестовом режиме — 2 с).

## 5. Настройки

### Переменные окружения на борту (без пересборки)
| Переменная | По умолчанию | Что делает |
|---|---|---|
| `SAR_GROUND_IP` | 192.168.3.24 (в run.sh) | адрес ноутбука |
| `SAR_FC_URI` | полётник Foxeer by-id | порт полётника; пусто — без полётника |
| `SAR_FAKE_POSE` | выкл (в `run.sh test` вкл) | подставная позиция `шир,долг,высота` |
| `SAR_ARUCO` | 1 | `0` — не искать маркеры |
| `SAR_ARUCO_REPEAT_S` | 15 (test: 2) | повтор одного маркера, с |
| `SAR_ARUCO_GAP_S` | 1.5 | пропал дольше — новая встреча |
| `SAR_VIDEO` | 1 | `0` — без живого видео |
| `SAR_VIDEO_FPS` | 5 | кадров видео в секунду (8–10 — плавнее, ~2 Мбит/с) |
| `SAR_VIDEO_WIDTH` | 640 | ширина кадра видео |
| `SAR_VIDEO_JPEG` | 60 | качество JPEG видео |

### Константы в `src/main.cpp` (нужна пересборка: `cmake --build build -j4` или просто `./run.sh`)
| Константа | Сейчас | **Перед полётом проверить** |
|---|---|---|
| `CAMERA_HFOV_DEG` | 62 | угол обзора камеры по горизонтали из даташита. Ошибка 5 % ≈ 1.3 м на 80 м |
| `CAMERA_TILT_DEG` | 0 | 0 = камера строго вниз, верх кадра — нос дрона. 2° ≈ 2.9 м на 80 м |
| `CAMERA_PAN_DEG` | 0 | поворот камеры вокруг вертикали |
| `CAPTURE_LATENCY_US` | 120 мс | задержка камеры; ошибка даёт снос меток вдоль полёта |
| `CONF_THRESHOLD` | 0.35 | порог уверенности нейросети |

Мосту нужны те же HFOV/наклон только для пятна обзора на карте
(`python ground_bridge.py --hfov 62 --tilt 0`); для находок борт присылает их сам.

## 6. Нюансы и что делать, если…

**Видео остановилось, когда дрон взяли в руки / тряхнули.**
Отходит USB-камера: она на долю секунды отключается. Программа сейчас этого
**не переживает** — зависает молча (лог перестаёт расти). Мало того, камера
возвращается с **другим номером** (`/dev/video1` вместо `/dev/video0`), и `run.sh`
после перезапуска пишет «Не удалось открыть камеру».
- Закрепить кабель камеры (стяжка, термоклей у разъёма) — в полёте вибрация сильнее.
- Перезапустить: `pkill -INT -f "[b]uild/sar_yolo_pipeline"`, затем `./run.sh test`.
- Если пишет «Не удалось открыть камеру» — в `run.sh` заменить
  `device=/dev/video0` на постоянный путь
  `device=/dev/v4l/by-id/usb-Jieli_Technology_USB_Composite_Device-video-index0`
  (или перезагрузить плату). Проверить: `v4l2-ctl --list-devices`.

**Дрон не подключается к мосту** («Жду подключения дрона»).
- Мост запущен? Адрес в `SAR_GROUND_IP` совпадает с тем, что печатает мост?
- Проверить с платы: `timeout 5 bash -c "</dev/tcp/<IP_НОУТБУКА>/5700" && echo OK`.
  «Connection refused» — мост не запущен или не тот адрес; таймаут — файрвол или VPN.

**«Порт 5700 занят».** Уже запущен второй мост, `ground_server.py` или `viewer.py`
Иры. Слушать порт может что-то одно.

**«Полётник не подключён / молчит».** Открыт Betaflight Configurator или
`msp_probe.py` — закрыть (`run.sh` об этом предупреждает). Проверить:
`ls -l /dev/serial/by-id/`.

**«Нет фикса GPS» / находки без координат.** На улице дождаться фикса 3 и ≥6 спутников.
Высота берётся с барометра от точки взлёта — **взводить дрон на земле** в месте старта.

**ArUco не распознаётся.**
- Нужно **белое поле вокруг чёрной рамки** — минимум в одну клетку, лучше белая бумага.
  Маркер, вырезанный по чёрной рамке и положенный на стол, не находится.
- Борт ищет словарь **DICT_4X4_50**: 4×4 клетки рисунка + чёрная рамка = 6×6 клеток
  всего, номера 0–49. Маркер 8×8 клеток с рамкой — это 6×6, он не распознается.
- Искать «все словари сразу» нельзя: один словарь ≈ 100 мс на кадр, все — ~1.5 к/с.

**Рамка маркера на видео подрагивает.** Маркер ищется на соседнем кадре
(сдвиг до ~250 мс), и видео идёт 4–5 к/с. Улучшить можно (поиск маркера на
том же кадре, 8–10 к/с, удержание рамки) — пока не сделано.

**Один человек — несколько строк в журнале.** Трекера на борту нет: один и тот же
человек раз в 5 секунд приходит новой находкой. Ложные/повторные — отмечать ✗.

**Wi‑Fi на плате с энергосбережением** (`iwconfig` → `Power Management:on`) — бывают
задержки и короткие обрывы. Выключить до перезагрузки:
`sudo iw dev wlan0 set power_save off`.

**Время в интерфейсе** — по часам платы. Если на плате нет интернета, часы могут
уйти; проверить `date`.

## 7. Что изменено относительно кода Иры (передать Ире!)

Резервные копии на плате: `src/main.cpp.before_bridge`, `include/Finding.hpp.before_bridge`.
Папка `onboard/` в архиве — исходники бортовой программы со всеми правками ниже, как на плате
(21.10.2026, рабочая сборка); отличаются только два файла из п. 4.
Плату перепрошивать не нужно: там уже всё собрано.

1. **`include/Finding.hpp`** — в метку находки **добавлены** поля (старые не менялись):
   `u, v` (пиксель), `bbox`, `img_w, img_h`, `hfov_deg`, `cam_tilt_deg`, `cam_pan_deg`,
   `drone_lat, drone_lon, alt_m, roll_deg, pitch_deg, yaw_deg` (поза на момент кадра).
2. **`src/main.cpp`, баг:** находка человека могла уйти **пустой** — уверенность 0,
   рамка `[0,0,0,0]`, точка в углу кадра, на карте мимо на десятки метров. Подтверждение
   считалось по окну 2 с, а отправлялась детекция текущего кадра, даже если в нём
   человека не было. Исправлено: отправка только из кадра, где цель есть
   (`if (!found[cls]) continue;`).
3. **`include/LiveVideo.hpp` (новый) + `src/main.cpp`** — живое видео на порт 5701,
   плюс рамки ArUco в видео.
4. **Расхождения версий:** `include/FindingImage.hpp` и `tools/ground_server.py` в
   `sar-drone-onboard-main.zip` Иры **новее**, чем на плате (там исправлено рисование
   рамки и приём телеметрии). Плата собрана и работает со старыми; в `onboard/` лежат **новые** из zip.
   Если пересобирать плату из `onboard/` — попадут новые, это нормально.
